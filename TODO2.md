This review changes documentation only. It does not implement the proposed fixes or change the original TODO checkboxes.

## Release-blocking corrections

Priority P0 here means possible state loss or an unsafe recovery result; P1 means a serious protocol, correctness, or delivery defect. Every task is open; reproduced findings are distinguished from source-based recommendations.

- [ ] **R01 — P0 · Replay final state, not TTL-sensitive historical commands.** `src/server.ts:1350-1364,1400-1405,1673-1679`; `src/persistence.ts:227-268`. Confirmed with a server-written AOF and a controlled clock: SET an expiring counter to 10, INCR before expiry, then recover after the deadline. Recovery creates a persistent value of 1. SET a second expiring key and PERSIST it before the deadline: that key is lost during recovery. Replaying SET first drops the old value based on recovery time; later INCR/PERSIST/EXPIRE cannot reconstruct its original state. Log resulting value plus absolute deadline/tombstone, or use a replay model that correctly reconstructs historical state before expiry filtering. Acceptance: restart equivalence for INCR/DECR, PERSIST, TTL extension, TTL shortening, immediate expiry, and these operations inside transactions. Keep legacy relative-TTL records explicitly versioned rather than silently promising exact old-log recovery.

- [ ] **R02 — P0 · Do not rotate the authoritative AOF after an export-only SAVE.** `src/server.ts:780-807`. Confirmed: save the configured checkpoint, write a new key, SAVE to another path, then restart with the configured path. The new key disappears because the alternate save removed its AOF record. Rotate only after advancing the checkpoint startup will use, or atomically update a manifest that selects the new checkpoint. Acceptance: alternate-path SAVE is a nondestructive export by default; restart retains every accepted post-checkpoint mutation.

- [ ] **R03 — P0 · Seed AOF sequence from the snapshot even when the log file is missing.** `src/persistence.ts:413-422,452-453`. The ENOENT return skips sequence initialization. Confirmed: after loading a snapshot covering sequence 1 without an AOF, the next write reuses sequence 1; the following restart skips it. Apply the snapshot sequence floor before all early returns. Acceptance: missing, empty, rotated and recreated AOF files assign strictly newer sequences and survive two restarts.

- [ ] **R04 — P0 · Validate snapshots completely before replacing live state.** `src/persistence.ts:198-224`; `src/cache.ts:730-764`. Confirmed: loading a valid JSON envelope with an oversized value clears an existing key before throwing. `restore()` also accepts `expiresAt: 'never'` at runtime, leaves the key live, and returns NaN from TTL. Validate entry shapes, key/value limits, finite deadlines, duplicate-key policy, metadata and version before mutation; stage restoration then atomically swap. Acceptance: every malformed/unsupported snapshot leaves data, bytes, TTLs, versions and LRU unchanged, emits no successful-load invalidation, and returns a useful typed error.

- [ ] **R05 — P1 · Make AOF corruption handling record-atomic and runtime-independent.** `src/persistence.ts:89-147,336-345,384-409,433-449`. Confirmed: a truncated final object is classified corrupt on Node 22 because V8 says `Expected ',' or '}'...`, not `Unexpected end of JSON input`. Also confirmed: a multi-entry AOF MSET can apply its first entry before a later invalid value marks the record corrupt. Do not classify truncation by a single engine error string; define a framed/committed-record policy, validate complete records, and stage each record atomically. For a partial append that throws, fail closed or repair to the last known-good offset before acknowledging more writes. Acceptance: truncate records at every byte boundary; test malformed middle lines, partial append/ENOSPC faults, invalid UTF-8, MSET/transaction rollback, and append-after-repair across supported Node versions. Do not broaden tail tolerance to silently ignore arbitrary corruption.

- [ ] **R06 — P1 · Preserve command and response FIFO across asynchronous SAVE/LOAD.** `src/server.ts:1096-1101,1751-1774`; `src/client.ts:728-748`. Confirmed on a raw connection: pipelined SAVE then PING returns PONG before OK. The client matches replies to pending requests by FIFO, so answers are delivered to the wrong promises. Serialize each connection's dispatch through asynchronous completion or use ordered response slots plus well-defined operation ordering. Acceptance: SAVE/LOAD mixed with PING, GET, writes, errors and QUIT keep request/reply association intact; a failed asynchronous command cannot reorder later replies.

- [ ] **R07 — P1 · Select HTTP versus RESP once per connection.** `src/server.ts:1085-1096`. Confirmed: splitting a legal PING frame immediately before its alphabetic payload produces no RESP reply; the second chunk is interpreted as an HTTP method. Track an explicit undecided/RESP/HTTP state and never resniff payload chunks. Acceptance: every split position of valid commands, including keys and JSON payloads, behaves identically to a single-chunk command; retain the split-HTTP-method regression.

- [ ] **R08 — P1 · Make WATCH versions immune to expiry and tombstone ABA.** `src/cache.ts:388-403,1027-1032,1149-1167`; `src/server.ts:1431-1433,1489-1494`. Confirmed: an expired watched key is not a conflict until another call notices expiry. Confirmed separately with `maxEntries: 1`: delete a watched key, churn about 1,100 keys so its tombstone is pruned, then recreate it; generation returns to 1 and a stale transaction commits. Use monotonic generations plus a safe absent-key epoch/watcher-retention scheme; evaluate expiry at watch/commit boundaries. Acceptance: expired-but-unswept, delete/recreate, absent-key churn, eviction and LOAD all detect relevant conflicts without unbounded version metadata.

- [ ] **R09 — P1 · Repair ignored CLI controls.** `src/cli.ts:38-61,102-116,190-203`. `--no-load` and `--no-save-on-shutdown` are stored under their full names, but main reads `load` and `save-on-shutdown`; both are ignored. The documented `--tls-min-version` is also not applied. A stubbed CLI option-resolution probe confirmed none of these controls reached the server options. Normalize negations, use an explicit option schema, reject unknown flags, and merge flags before validating the effective configuration. Acceptance: command-level tests verify each advertised flag, missing values, unknown names, env precedence and TLS option preservation without binding a public port.

- [ ] **R10 — P1 · Fix the Docker install/build lifecycle.** `Dockerfile:9-14`; `package.json:45`. `npm ci` runs `prepublish: npm run build` before Docker copies tsconfig or src. A package-only offline install reproduced exit 1 and TypeScript help output. Move publishing-only build work to `prepack`/`prepublishOnly` as appropriate, or explicitly suppress lifecycle scripts during the dependency stage and build after copying source. Acceptance: build the image from a clean checkout with no dist, run the non-root container on a writable data volume, and verify readiness plus snapshot/restart and configured TLS/mTLS healthchecks.

## Scalability and resource bounds

- [ ] **S01 — P1 · Bound accumulated work, not only individual frames.** `src/server.ts:219-236,960-1001,1425-1468,1691-1718`. MULTI queues, repeated WATCH keys, subscriptions and accepted connections can grow without a total budget while every frame remains legal. Add configurable transaction command/byte limits, watch/subscription caps, max connections and global in-flight byte budgets; release accounting on every abort/close. Coalesce autosaves or cap persistence-queue depth rather than letting intervals enqueue indefinitely (`server.ts:771-774,951-957`). Acceptance: sustained clients remain within explicit process-memory budgets and overload returns predictable errors without affecting other connections.

- [ ] **S02 — P1 · Enforce compatible input/output limits end-to-end.** `src/server.ts:1003-1048,1104-1111,1615-1621`; `src/protocol.ts:79-118,234-258`. The first socket write bypasses the pending-output cap, large MGET/EXEC replies allocate completely before backpressure, and server replies can exceed the client's fixed 8 MiB frame/1,024-item limits. Cache value limits can be raised without changing either decoder. Confirmed: a complete 17 KB HTTP header receives 200 because the header limit is checked only while its terminator is absent. Include writableLength and encoded reply bytes in budgets, enforce the HTTP limit even on complete headers, and validate/chunk large requests or negotiate compatible limits. Acceptance: maximum valid writes remain readable; oversized batch replies fail predictably before large allocation; slow-reader tests observe bounded total memory.

- [ ] **S03 — P1 · Bound client queues and connection establishment.** `src/client.ts:643-725,754-779,1128-1176,1374-1395`. Request timeouts begin only after dial, TCP/TLS establishment has no explicit deadline, and pending arrays/socket writes have no capacity or drain handling. Add connect/TLS/auth deadlines, AbortSignal support, maximum pending commands/bytes, bounded transaction connection allocation and jittered backoff. Prefer healthy connections by pending load rather than only round-robin. Acceptance: unreachable/blackholed endpoints and a slow server settle by a defined total deadline, close cancels outstanding dials, and memory remains bounded without automatically retrying non-idempotent writes.

- [ ] **S04 — P2 · Budget expiry and namespace scans.** `src/cache.ts:544-557,858-867`. Both prefix clearing and sweeping allocate arrays over the full cache; the default sweeper scans persistent keys too. Start with a bounded cursor/time budget and direct safe iteration; consider an expiry heap/timing wheel and namespace membership index only after workload measurements. Acceptance: expiry lag, event-loop delay and peak allocation are measured at increasing cache sizes, with exact bytes/versions/invalidation semantics preserved.

- [ ] **S05 — P2 · Bound L1 state and make invalidation gaps observable.** `examples/production-integration.js:59-60,79-110`; `src/client.ts:916-947`; `src/pubsub.ts:12-20`. The example's Map never evicts untouched stale keys, and existing subscription loss has no application-facing status event. Add L1 entry/byte/age limits and bounded single-flight concurrency; expose disconnect/resubscribe lifecycle events so callers can invalidate L1 promptly. For stronger coherence, add server epoch/monotonic event IDs and reset-on-gap semantics; do not market best-effort pub/sub as reliable replication. Acceptance: long-running high-cardinality traffic stays bounded and reconnect tests detect gaps without silently serving indefinitely stale L1 values.

- [ ] **S06 — P2 · Define capacity and partitioning boundaries before scale-out.** `src/server.ts`, `src/cache.ts`, `src/executor.ts`. SQL rows/indexes are not governed by KV maxBytes, and independent servers have no shared transaction/invalidation domain. Add SQL row/byte/result budgets and metrics for heap/RSS, event-loop lag, queue bytes, active transactions, reconnects and persistence duration. Publish measured single-instance limits. If sharding is required, define key routing, ownership, cross-key transaction boundaries and failure behavior first. Acceptance: a representative workload has documented memory/latency SLOs and capacity tests; no unsupported cross-server atomicity or replication claims.

## Speed and efficiency

- [ ] **P01 — P1 · Replace whole-cache transaction snapshots with an efficient rollback design.** `src/cache.ts:329-379`; `src/server.ts:1271-1285,1470-1471,1500-1520`. Every AOF-backed write captures/clones all resident values and versions, not just the modified key. A local probe of 100 facade SETs took about 6.43 ms with no seeded entries, 27.06 ms with 100, and 62.27 ms with 1,000 entries containing small objects. This is a small noisy measurement, not a capacity estimate, but agrees with the linear code path. Use an undo journal/copy-on-write write set that also captures TTL, LRU changes, eviction victims, stats and versions, or validate/stage a commit before append. Acceptance: fixed-size writes scale with touched state, not resident payload size, while all rollback and failure tests remain green. The diagnostic seed used the private cache only to exclude seed-write overhead from timing, not as an endorsed API.

- [ ] **P02 — P2 · Make RESP decoding truly incremental and reduce copies.** `src/protocol.ts:121-132,151-220,234-256`; `src/server.ts:977-979`; `src/client.ts:731-734`. Partial arrays are reparsed from the beginning, and each chunk can concatenate the accumulated frame again. UTF-8 validation also re-encodes every decoded string. Use a segmented buffer/parser cursor and resumable array state; benchmark a strict TextDecoder or equivalent one-pass UTF-8 validator. Avoid redundant Buffer.from copies and use head-index/deque queues instead of repeated shift under large backlog. Acceptance: fragmented large frames show near-linear processing and all malformed-input/resource-limit behavior is preserved.

- [ ] **P03 — P2 · Give primary keys a dedicated uniqueness index.** `src/executor.ts:392-422,536-539,685`. INSERT scans existing rows and uses seen.some for every candidate; a large batch is quadratic. UPDATE validates all primary keys even when the PK is unchanged. Maintain a dedicated uniqueness structure independent of optional query indexes; use staged batch validation and skip unchanged PK work. For structured ANY keys, either specify canonical structural identity or restrict PK types explicitly. Acceptance: insert/update scaling and heap costs are benchmarked at 1k/10k/100k rows, including duplicates inside one batch and failed-update rollback.

- [ ] **P04 — P2 · Avoid rebuilding all indexes after one-row DELETE.** `src/executor.ts:703-744`; `src/types.ts:34-40`. Candidate lookup helps predicate evaluation, but array filtering and positional index rebuilding still touch the table. Consider stable row IDs with tombstones/compaction or an indirection layer so deletions update only affected index memberships. Acceptance: selective DELETE cost tracks affected rows/indexes outside scheduled compaction, with randomized indexed-versus-scan consistency tests after mixed writes.

- [ ] **P05 — P2 · Improve query planning and avoid unnecessary full work.** `src/executor.ts:206-257,556-620,938-954,968-1074`. Mixed AND drops a usable equality index when the other predicate needs a scan; LIMIT is applied after full filtering/sorting; LIKE recompiles a regex for every row; explain and execution duplicate planning logic. Use selective available candidates with residual filtering, early LIMIT/OFFSET termination where valid, top-k selection for ORDER BY LIMIT, and bounded prepared-statement/predicate compilation. Prefer a bounded-work LIKE matcher for repeated wildcard patterns. Evaluate range/composite indexes only against real queries and memory/write budgets. Acceptance: EXPLAIN reports one shared real plan and measurements show fewer examined rows/allocations without changing results.

- [ ] **P06 — P2 · Turn benchmark scripts into trustworthy regression evidence.** `benchmark/load.js:87-133,149-299`; `benchmark/indexes.js`. Current runs include Promise/microtask overhead for synchronous operations, colocate network client/server, benchmark no-op in-process fanout, and time direct AofLog appends rather than AOF-enabled server mutations. Snapshot seeds are capped at 1,000; memory sampling misses transient synchronous peaks. Add warmup, repeated runs, separate client/server processes, observed hit ratios, realistic object sizes, AOF on/off, TLS, real network subscribers/slow readers, restart replay and failure workloads. Measure event-loop lag, sampled RSS/heap/external bytes, CPU, p50/p95/p99 and GC. Acceptance: machine/runtime/seed metadata accompanies baselines and CI catches regressions with noise-tolerant thresholds; smoke results are not presented as production throughput.

## Serialization and persistence design

- [ ] **Z01 — P1 · Centralize bounded JSON validation, cloning and serialization.** `src/cache.ts:109-174,431-446,579-591`; `src/client.ts:364-397`; `src/server.ts:1289-1345,1579-1620`; `src/value.ts`. Values may be traversed repeatedly for validation, cloning, size estimation, wire output and AOF. Recursive cloning has no depth/node budget and size rejection happens after traversal. Reject accessors/custom serialization hooks or capture data once: the facade currently caches a clone but logs the original value, so a changing getter/toJSON can make memory and AOF disagree. Define supported JSON values, special keys, depth/nodes/bytes and ownership in one module. Retain structural equality; canonical JSON is needed only for stable hashes/fixtures or deterministic structured ordering. Acceptance: equivalent boundary behavior, immutable owned storage, bounded deep/wide-input processing, and stored/logged/wire values agree byte-for-byte or structurally as specified. Measure any cached serialized representation's extra memory before adopting it.

- [ ] **Z02 — P1 · Reconcile number, TTL and RESP integer domains.** `src/cache.ts:601-635,768-781`; `src/protocol.ts:79-82,135-143`; `src/server.ts:1647-1649,1673-1682`. Confirmed: encodeInt accepts `Number.MAX_SAFE_INTEGER + 1`, but RespDecoder rejects it. INCR accepts finite numbers and emits an int for Number.isInteger results, so accepted mutations can become unreadable replies. Fractional TTLs can also produce fractional remaining TTLs that cannot be encoded as RESP integers. Decide on safe integer counters or a documented floating/bulk representation; specify TTL rounding/range. Acceptance: encoder/decoder symmetry at safe-integer boundaries, large finite numbers, exponent notation, fractional TTLs, negative zero and overflow; precision loss is never silent. Add a tagged versioned format only if BigInt or richer types are a real requirement.

- [ ] **Z03 — P2 · Bound persistence memory and make the format evolvable.** `src/persistence.ts:149-224,348-381,413-453,462-518`. Snapshots materialize cloned entries plus a full JSON string; startup reads/parses the AOF twice, and rotation synchronously reads/splits/rewrites the entire log. Add file/record/count/depth limits before allocation; stream replay and snapshot serialization where consistency permits; rotate/rewrite by size/age as well as time. Define versioned envelopes, sequence/epoch linkage, checksums/commit markers, migration rules and durable-ack policy (never/everysec/always or equivalent) explicitly. Serialize public same-path save helpers or document concurrency ownership. Acceptance: bounded peak memory and event-loop delay on large files, unknown versions fail without mutation, and crash/fault tests cover append, sync, rename, directory sync and checkpoint selection. Benchmark JSON against a binary codec before introducing compression or format complexity.

- [ ] **Z04 — P1 · Preserve eviction outcomes during recovery or narrow the guarantee explicitly.** `src/cache.ts:407-423,506-521`; `src/persistence.ts:227-268`; `README.md:419-426`. Confirmed with capacity 2: SET a, SET b, GET a, SET c leaves a/c live; AOF recovery produces b/c because GET's LRU effect and the eviction outcome are absent from the log. This can resurrect an evicted counter/lock-like value and drop a live entry. Persist final mutation effects including eviction tombstones, or document and enforce a weaker cache-warming-only recovery mode that is unsuitable for correctness-sensitive counters/locks. Acceptance: replay with intervening reads, evictions, transactions and changed capacity has explicit, tested semantics; don't log every GET solely to reproduce LRU if recording write outcomes solves the problem.

## Recommended implementation order and completion criteria

First repair recovery/checkpoint safety (R01-R05, Z04), wire ordering/detection (R06-R07), WATCH (R08), CLI/Docker delivery (R09-R10), and the contract tests needed to prevent recurrence. Then finish SQL/API/value semantics and resource budgets. Optimize transaction copying, parser buffering and SQL indexing only after the correctness suite is green, measuring each change against the same fixtures.

Completion requires a clean build, typecheck, all test suites and package consumer checks passing on the supported runtime matrix; end-to-end image/TLS checks; deterministic restart and disk-fault regressions; and representative performance/resource evidence. Update the original checkboxes only when that evidence exists. An implemented code path or a small benchmark run alone is not proof that a TODO is complete.
